# Лабораторная работа 5. ООП: классы, объекты и инкапсуляция

**Индивидуальный вариант:** 1 - учет посещаемости (с уважительными пропусками).

## Состав
- `attendance.py` - классы `StudentAttendance` и `AttendanceJournal`.
- `main.py` - демонстрационный запуск.
- `tests/test_attendance.py` - 10 автоматических тестов (3 ошибочных сценария и более).

## Запуск (из папки Lab 5)
```bash
python main.py
python -m unittest discover -s tests -v
```
Ожидаемый вывод:
```
Amina: 80.00%; допущен
Dias: 66.67%; не допущен
Mira: -; нет данных
```

## Таблица классов

| Класс | Ответственность | Атрибуты | Методы | Инварианты |
|-------|-----------------|----------|--------|-----------|
| StudentAttendance | посещаемость одного студента | student_id, name, _records | mark_present, mark_absent, present_dates, absent_dates, excused_dates, attendance_rate, status | id > 0; имя не пустое; на одну дату одна отметка; дата это datetime.date |
| AttendanceJournal | регистрация студентов и отчет | _students | register, mark_present, mark_absent, find, report | id уникальны; значения словаря это StudentAttendance |

Взаимодействие: `AttendanceJournal` находит студента по id и передает ему отметку, а все проверки делает `StudentAttendance`.

## Правила
- Процент = присутствия / (присутствия + неуважительные пропуски) * 100. Уважительные пропуски в расчет не входят (повышенная сложность).
- Допуск при проценте не ниже 70.
- Если нет учитываемых занятий, процент None, статус "нет данных".

## Вывод
Инкапсуляция здесь в том, что отметки лежат во внутреннем словаре `_records`, а наружу даются только tuple-снимки и методы-команды. Все проверки (тип даты, повтор отметки, id, имя) выполняются до изменения состояния, поэтому объект всегда остается корректным. Процент не хранится в поле, а считается свойством, значит он не может разойтись с отметками.

## Ответы на контрольные вопросы
1. Класс это шаблон, экземпляр конкретный объект, созданный по нему.
2. Идентичность отличает объект, состояние это значения его атрибутов, поведение это методы, которые это состояние меняют или показывают.
3. `__init__` создает корректное начальное состояние или сообщает об ошибке исключением.
4. Атрибут класса общий для всех экземпляров, изменение списка в одном объекте затронет все остальные.
5. `self` это ссылка на текущий экземпляр, с которым работает метод.
6. Инкапсуляция это объединение данных и правил их изменения в одной границе, а не просто запрет доступа.
7. Инвариант это условие, верное для любого корректного состояния объекта. Проверять его нужно в `__init__` и в методах-командах до изменения состояния.
8. Чтобы клиент не мог изменить внутренний список напрямую и нарушить инвариант.
9. Команда меняет состояние (mark_present), запрос только возвращает данные (attendance_rate).
10. Два подчеркивания только искажают имя (name mangling), доступ все равно возможен, это не защита.
11. Student отвечает за свои данные и правила, GradeBook за коллекцию студентов, поиск и рейтинг. Здесь то же самое: StudentAttendance и AttendanceJournal.
12. Тесты через публичный интерфейс проверяют контракт класса и не ломаются при смене внутренней реализации.
