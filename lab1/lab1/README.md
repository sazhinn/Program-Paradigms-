# Лабораторная работа 1. Сравнение парадигм программирования (Python)

Сквозная задача: сумма квадратов чётных чисел списка `[4, 7, 2, 9, 12, 5, 8, 3]`, ответ 228.

| Файл | Что внутри |
|------|-----------|
| src/01_imperative.py | императивный стиль |
| src/02_procedural.py | процедурный стиль |
| src/03_oop.py | ООП |
| src/04_functional.py | функциональный стиль |
| src/05_event.py | событийный стиль (tkinter) |
| src/variant1_*.py | индивидуальный вариант 1 (сумма квадратов положительных), 3 стиля, ответ 109 |

## Сравнение

| Критерий | Императивный | Процедурный | ООП | Функциональный |
|----------|--------------|-------------|-----|----------------|
| Основная единица | Команда | Функция | Объект | Преобразование |
| Переменная total | Есть | Есть внутри функции | Есть внутри метода | Не требуется |
| Декомпозиция | Минимальная | По функциям | По ответственности класса | По операциям |
| Расширяемость | Низкая | Средняя | Высокая | Высокая для коллекций |
| Объём кода | Средний | Средний | Большой | Минимальный |

## Вывод

Самым понятным для новичка получился императивный вариант, потому что там видно каждый шаг. Меньше всего изменяемого состояния в функциональном решении, там нет ни одной изменяемой переменной. Проще всего тестировать процедурный и функциональный код, так как функции зависят только от входных данных. Для расширения лучше подходит ООП, потому что в класс легко добавлять новые методы (как count_even_numbers или find_maximum). Для обработки коллекций я бы выбрал функциональный стиль, он короче всех. На практике парадигмы часто смешивают в одной программе.
